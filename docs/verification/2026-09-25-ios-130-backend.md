# iOS 1.3.0 backend integration verification

## Scope

Integrated the 1.3 follow-up and learner-authored question backend from `83e0ed83`
onto `810db163` in `codex/ios-130-testflight`. Resolved all backend conflicts while
retaining the newer canonical Voice Tutor records, strict answer/skip transitions,
question-generation commit recovery, voice quota policy, and billing code.

- Optional private follow-ups reuse the asynchronous generation Saga, normal
  one-question reservation/commit/release, idempotency, owner checks, and a maximum
  of two descendants per original. Skipped/deleted descendants retain their slot.
- Private custom question-and-answer records remain synchronous and unscored,
  consume no generation quota, and preserve pending drafts.
- Canonical record projections preserve `voice_tutor` as well as new source and
  parent/root/depth metadata. Voice `COMPLETED` records cannot start a follow-up.
- Topic ability/growth aggregates and the latest records used for score charts
  exclude supplementary questions. Node learning history includes custom answers
  alongside existing graded questions and voice records.
- Existing owner detail reads continue to return skipped records for terminal
  reconciliation; browse/pending pages hide skips and follow-up thread history
  retains them.
- Existing Voice Tutor error numbers 511/512 are unchanged. Follow-up unavailable
  and limit errors use new numbers 517/518; named codes are unchanged.
- New application services implement inbound use cases. Follow-up composition
  depends on generation/browsing use cases; custom persistence uses outbound
  ports. Both controllers depend on controller-facing web ports.

and voice-shaped rows, then applies V121/V122 and checks preserved values,
privacy/no-score/lineage uniqueness, and the retained V105 voice shape constraint.
The migration test drops only its own randomly named database.

## Environment and command

Verification uses GraalVM JDK 25.0.2, an isolated MySQL 8.0.32 instance on
`127.0.0.1:33371`, and an isolated Redis instance on `127.0.0.1:36391`.
The disposable MySQL database uses `utf8mb4_0900_ai_ci`, matching current migration
V1 tables. No configured production/user database or service is used. Provider
calls in study API tests use the existing fake OpenAI adapter; stream consumers
and schedulers are disabled.

```sh
JAVA_HOME=/Library/Java/JavaVirtualMachines/graalvm-jdk-25.0.2+10.1/Contents/Home \
BUDDYSTUDY_TEST_MYSQL_PORT=33371 REDIS_HOST=127.0.0.1 REDIS_PORT=36391 \
./gradlew \
  :application:test --tests '*FollowUpQuestion*' --tests '*QuestionGeneration*' \
    --tests '*StudyRecordMappersTest' --tests '*CustomQuestionServiceTest' \
    --tests '*StudyRecordWrite*' --tests '*VoiceRecord*' --tests '*ApiErrorCodeTest' \
```
