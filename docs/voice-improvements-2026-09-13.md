재시도는 쓰기 이전의 `INPUT_PERSISTENCE_PENDING` 오류에만 적용합니다.
결과가 불명확한 타임아웃이나 일반 오류는 자동으로 다시 실행하지 않습니다.
새 재시도는 최초 결과 이후 3초 안에서만 시작하며, 실행 중인 요청에는
기존 전체 도구 제한시간 15초가 계속 적용됩니다. 여러 내부 시도는 하나의
MCP 실행 이력으로 표시됩니다. 줄어드는 것은 반복 API/저장소 호출이며,
OpenAI 토큰 절감률을 실측했다고 주장하지 않습니다.

## 남은 개선 우선순위

| 우선순위 | 항목 | 완료 기준 |
| --- | --- | --- |
| 높음 | 질문 준비 실패에서 직접 복구 | 원 UI의 복구 버튼을 정확한 study/record/correlation에 연결하고, 기존 생성 여부를 확인한 뒤 필요한 작업만 실행. 중복 생성·과금과 늦은 복구 결과의 화면 교체를 차단. |
| 높음 | 단어 끝에서 정확히 멈추기 | 현재 AI 음성을 유지하고 추가 지연 약 1초 안에 실제 단어 끝을 확인. 현재 무음 간격 기반 중단은 이 조건을 보장하지 않음. 기존 측정에서 iPhone 기본 인식기의 확정 시간은 조건을 충족하지 못했으므로 완료로 분류하지 않음. |
| 중간 | 강제 종료 전 녹음 복구 | 최종 manifest 생성 전 프로세스가 종료돼도 동의받은 원본의 복구 대상을 식별. 계정 변경·삭제와 보호된 데이터 잠금 경계를 함께 검증. 현재 짧은 background lease는 강제 종료까지 보장하지 않음. |

권한·구독/요금 정책과 wire protocol에는 변경이 없습니다.
